# T1069.003 — Permission Groups Discovery: Cloud Groups

## Summary

Rejewski emulates an adversary enumerating cloud-based permission groups in the target tenant. Group enumeration is the immediate follow-on to T1087.004: once accounts are known, group memberships reveal effective privilege and identify high-value targets such as admin groups, role-assignable groups, and sensitive distribution lists. Sprint 1 keeps the surface read-only and intentionally narrow — directory roles and transitive membership are deferred to Sprint 2+.

## ATT&CK reference

<https://attack.mitre.org/techniques/T1069/003/>

## Borrowed client

Microsoft Graph Command Line Tools (14d82eec-204b-4c2f-b7e8-296a70dab67e). Inherits the borrowed-client decision from T1078.004.

## Procedure

1. Operator confirms a valid Graph token from T1078.004 is in scope.
2. Operator calls GET /groups to enumerate the tenant's groups; results paged at default 100/page until the directory is exhausted or the configured row cap is hit.
3. Operator calls GET /me/memberOf to capture the caller's direct group memberships (overlaps T1087.004 by design; T1069.003 focuses on the group side of the join).
4. Operator records each response correlation ID, page count, and group count into the run evidence ledger.

## Guardrails

- G-1 (consent-bound tenant lock, ADR 0008): all Graph calls target the one tenant named in the run's consent record; the evidence in this repo comes from the lab tenant.
- G-3 (consent floor): only Group.Read.All and User.Read scopes; no Group.ReadWrite.All in Sprint 1.
- G-5 (evidence capture): correlation IDs, page counts, and aggregate group counts logged per call.
- G-6 (audit log redaction): group display names and object IDs are hashed in evidence files where they could leak tenant structure to public-repo readers.

## Detection signals

- Graph audit log entries: bulk /groups enumeration from the FOCI client ID.
- Entra ID directory audit: group-read activity correlated to the T1078.004 sign-in session.

## Limitations

- GET /me/transitiveMemberOf is deferred to Sprint 2+ uplift. Sprint 1 captures direct memberships only.
- GET /directoryRoles enumeration is deferred to Sprint 2+ uplift. Role-assignable group discovery is therefore partial in Sprint 1.
- Privileged Identity Management (PIM) eligible vs active role assignment is out of scope for Sprint 1.
- Group expiration policies and dynamic group rules are out of scope.
