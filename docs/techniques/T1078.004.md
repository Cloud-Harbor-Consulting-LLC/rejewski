# T1078.004 — Valid Accounts: Cloud Accounts

## Summary

Rejewski emulates an adversary who has obtained valid cloud-only Entra ID credentials and authenticates to Microsoft Graph via the device-code flow against a first-party FOCI client. This is the entry point of every Sprint 1 emulation chain — no downstream discovery technique runs without a successful T1078.004 sign-in first. The module establishes the no-tenant-app-reg posture in code: the only application visible to the target tenant is Microsoft-owned.

## ATT&CK reference

<https://attack.mitre.org/techniques/T1078/004/>

## Borrowed client

Microsoft Graph Command Line Tools (14d82eec-204b-4c2f-b7e8-296a70dab67e). Selected because it is a Microsoft-published, FOCI-eligible client present in every Entra ID tenant by default; using it leaves no Rejewski-controlled application object in the sandbox tenant. The borrowed-client choice reaffirms the no-tenant-app-reg posture — gaining a tenant app registration is itself a Sprint 2+ technique, not a prerequisite.

## Procedure

1. Operator invokes the device-code flow against the FOCI client targeting the lab tenant.
2. Operator completes the device-code challenge using a seeded test-user credential (per B001 step 4 user seeding).
3. SDK receives a Graph-scoped access token; refresh token cached per session-keep-warm policy.
4. Operator validates token issuance by calling GET /me; a 200 response confirms valid sign-in.
5. Operator records token issuance timestamp, sign-in correlation ID, and tenant ID into the run evidence ledger.

## Guardrails

- G-1 (consent-bound tenant lock, ADR 0008): all Graph calls target the one tenant named in the run's consent record; the evidence in this repo comes from the lab tenant.
- G-2 (no tenant app registration): only the borrowed first-party client may be used.
- G-3 (consent floor): Sprint 1 token requests carry read-only Graph scopes; no Mail.Send, no Directory.ReadWrite, no write or delete scopes.
- G-4 (FOCI client allowlist): Graph Command Line Tools only in Sprint 1.
- G-5 (evidence capture): correlation ID, issuance timestamp, and tenant ID logged before any downstream technique runs.
- G-8 (time-boxed sessions): refresh tokens expire within the session-keep-warm window; long-lived persistence is out of scope.

## Detection signals

- Entra ID sign-in log entry with app ID 14d82eec-204b-4c2f-b7e8-296a70dab67e, device-code authentication method.
- Risky sign-in score nominal (sandbox test users; no risk indicators by design).
- Graph audit log records correlation ID matching the Rejewski evidence ledger.

## Limitations

- Sprint 1 covers cloud-only test accounts. Hybrid identities synced from on-prem AD are out of scope.
- Token persistence beyond the session-keep-warm window is not exercised.
- Sign-in conditional-access bypasses (location spoofing, device compliance manipulation) are deferred to Sprint 2+ defensive-evasion modules.
