# T1082 — System Information Discovery

## Summary

Rejewski will emulate an adversary who calls GET /organization to read the tenant's
top-level configuration record from Microsoft Graph. The organization object is a single
response (no pagination) containing the tenant's display name, country/region, city,
technical and security notification email addresses, on-premises synchronization state,
assigned service plans, provisioned plans, and all verified domain names. From this one
call, an attacker determines whether the tenant is hybrid (on-premises Active Directory
synchronized via Entra Connect) or cloud-only, which Microsoft workloads are licensed
and active, who holds the technical administrator contact role, and what custom domains
are registered. Hybrid tenants are of particular adversary interest because they
introduce an on-premises attack surface that Entra ID detects less reliably than
cloud-only environments. The provisioned plan list overlaps with the SKU-level detail
from T1518.001 (/subscribedSkus) but at a higher level of abstraction, making it a fast
pre-enumeration check before deeper licensing enumeration.

## Borrowed client

Microsoft Graph PowerShell (14d82eec-204b-4c2f-b7e8-296a70dab67e). Inherits the
borrowed-client decision from T1078.004; no separate client acquisition occurs.
No tenant-side application registration is created. The no-tenant-app-reg posture
(ADR 0001 §1, threat-model.md §3) is maintained throughout.

The Graph scope required for this technique (Organization.Read.All) is within the
standard delegated scope set pre-consented on the FOCI client for M365 enumeration.
No scope uplift is expected. Operators should verify Organization.Read.All consent
status in cloudharbordemo before the first Sprint 2 run.

## Required privilege

GET /organization requires Organization.Read.All, which is typically pre-consented on
the Microsoft Graph PowerShell FOCI client. Any authenticated user with this scope can
read the full organization object. No directory role (Global Reader, Global Admin, etc.)
is required beyond the scope grant. This keeps T1082 at the same privilege tier as
T1087.004 and T1069.003, making it runnable immediately after the T1078.004
initial-access step.

## Procedure

*Implementation pending Sprint 2. The procedure below defines the expected implementation
shape; it will be updated to reflect the actual script behaviour when Sprint 2 opens.*

1. Operator confirms a valid Graph token from T1078.004 is in scope.
2. Operator calls GET /organization to retrieve the tenant's organization object. The
   response is a single-object collection; no pagination is required.
3. Operator extracts and records the following fields:
   - displayName: tenant display name.
   - country and countryLetterCode: tenant billing country.
   - city: tenant billing city.
   - technicalNotificationMails: array of technical contact email addresses.
   - securityComplianceNotificationMails: array of security contact email addresses.
   - onPremisesSyncEnabled: true if Entra Connect sync is active (hybrid tenant).
   - onPremisesLastSyncDateTime: timestamp of the most recent directory sync.
   - assignedPlans: array of all Microsoft service plan assignments with status.
   - provisionedPlans: array of all provisioned plans (higher-level view than assignedPlans).
   - verifiedDomains: array of all verified domain objects including name, type
     (Managed/Federated), isDefault, isInitial, and capabilities.
4. Operator flags hybrid status: if onPremisesSyncEnabled is true, note this as a
   high-value finding — the tenant has on-premises infrastructure whose compromise
   could propagate into Entra ID via directory sync.
5. Operator produces a structured summary: tenant name, country, hybrid/cloud-only
   classification, security contact addresses, domain count, verified domain names,
   and provisioned plan names.
6. A replay-log entry (kind=graph_call) is written per G-5 requirements.

## Guardrails

- G-1 (sandbox tenant only): all Graph calls target cloudharbordemo 76b87c33-6178-4ff9-94a7-164792c8e4c6.
- G-3 (read-only scope): GET only; no organization property writes.
- G-5 (evidence capture): replay-log entry written per run; structured summary in
  evidence JSON.
- G-6 (audit log redaction): technicalNotificationMails and
  securityComplianceNotificationMails contain email addresses and are hashed in evidence
  files before any content reaches the public-repo samples/ directory; raw addresses
  remain in the operator-side SharePoint Evidence folder only.
- G-7 (no real user data): GET /organization returns tenant-level configuration only;
  no per-user data is read.
- G-9 (row cap): not applicable — the organization response is a single object.

## Detection signals

- Graph unified audit log: GET /organization call from the FOCI client ID (14d82eec).
  Organization-read operations log under the directoryManagement or organization audit
  category. This call has low volume in normal delegated usage and may stand out if
  issued by a non-admin account.
- Entra ID sign-in logs: correlatable via the T1078.004 session correlation ID.
- Microsoft Defender for Cloud Apps: a single organization-read call is unlikely to
  trigger anomaly detection in isolation; however, it is a consistent leading indicator
  of systematic tenant enumeration when chained with T1087.004, T1069.003, and T1526
  calls in the same session.

## Limitations

- GET /organization does not return per-user or per-device attributes; this technique
  covers only the tenant-level system configuration object.
- onPremisesSyncEnabled reflects the current sync state but does not reveal which
  specific on-premises OUs or objects are in scope for sync. Full sync scope
  enumeration requires Entra Connect-side access and is outside Graph's read surface.
- assignedPlans and provisionedPlans overlap with GET /subscribedSkus (T1518.001) but
  at lower resolution. The organization call provides a fast first-pass; T1518.001
  provides the authoritative per-SKU and per-service-plan breakdown.
- securityComplianceNotificationMails and technicalNotificationMails are often set to
  distribution lists or service accounts rather than individual owners, limiting their
  direct value for social engineering targeting.
- The verifiedDomains array duplicates some information available via GET /domains
  (T1482). T1482 provides additional federation metadata (federationConfiguration) not
  present in the organization object. Operators running both techniques should note the
  overlap in the evidence ledger.
