# T1087.004 — Account Discovery: Cloud Account

## Summary

Rejewski emulates an adversary who, having authenticated via T1078.004, enumerates user accounts in the target tenant via Microsoft Graph. Account discovery establishes the directory landscape — caller identity, peer accounts, and the caller's own group affiliations — that informs subsequent privilege-escalation and lateral-movement targeting. This module is read-only and stays within the consent floor declared in ADR 0001 §2.

## ATT&CK reference

<https://attack.mitre.org/techniques/T1087/004/>

## Borrowed client

Microsoft Graph PowerShell (14d82eec-204b-4c2f-b7e8-296a70dab67e). Inherits the borrowed-client decision from T1078.004; no separate client acquisition occurs.

## Procedure

1. Operator confirms a valid Graph token from T1078.004 is in scope.
2. Operator calls GET /me to capture caller identity (UPN, object ID, displayName).
3. Operator calls GET /users to enumerate directory accounts; results paged at default 100/page until the directory is exhausted or the configured row cap is hit.
4. Operator calls GET /me/memberOf to enumerate the caller's direct group memberships (used as input to T1069.003).
5. Operator records each response correlation ID, page count, and account count into the run evidence ledger.

## Guardrails

- G-1 (sandbox tenant only): all Graph calls target cloudharbordemo 76b87c33-6178-4ff9-94a7-164792c8e4c6.
- G-3 (consent floor): only User.Read and User.ReadBasic.All scopes; no Directory.Read.All in Sprint 1 (deferred to Sprint 2 uplift).
- G-5 (evidence capture): full response correlation IDs and aggregate counts logged; raw response bodies redacted per G-6.
- G-6 (audit log redaction): account UPNs, emails, and object IDs are hashed in evidence files; the unredacted index lives in the SharePoint Evidence folder with restricted access.
- G-7 (no real user data): only seeded test accounts populate the sandbox tenant.

## Detection signals

- Graph audit log entries: bulk /users enumeration calls from the FOCI client ID.
- Entra ID directory audit: account-read activity correlated to the T1078.004 sign-in session.
- Anomalous enumeration volume signals (when defender baselines are configured) may surface in Microsoft Defender for Identity or Entra ID Identity Protection.

## Limitations

- Sprint 1 caps enumeration at the configured row limit (default 50 accounts) to keep evidence files manageable; full-tenant enumeration is a Sprint 2 uplift.
- Service principals and application objects are out of scope for T1087.004; cloud service discovery covers that surface in a later sprint.
- Cross-tenant guest accounts are not enumerated separately in Sprint 1.
