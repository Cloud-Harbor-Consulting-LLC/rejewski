# T1114.003 — Email Forwarding Rule

## Summary

Rejewski emulates an adversary who discovers inbox forwarding rules that auto-redirect mail
to attacker-controlled or external addresses. The same script that implements T1114.002
Surface A — `scripts/tool_list_inbox_rules.py`, `GET /users/{id}/mailFolders/inbox/messageRules`
— directly surfaces T1114.003: each rule's `forwardTo`, `forwardAsAttachmentTo`, and
`redirectTo` action fields are the forwarding-rule artifacts an adversary either created for
persistence or discovers as evidence of prior implantation. Where **T1114.002** covers
*reading email content/metadata* (active remote collection), **T1114.003** covers the
*forwarding-rule mechanism* that auto-collects mail without any further active reads — a
persistence-flavoured collection surface. One script surfaces both sub-techniques from the same
rule inventory; this module governs the forwarding-rule (T1114.003) view.

**Read-only posture.** Rejewski's guardrails (G-1) make this an *enumeration* of existing
forwarding rules, not the *creation* of one. The tool answers "does a mail-forwarding path
already exist in this mailbox — the adversary's own, or a defender's, or a prior compromise's?"
It does not create, modify, or delete a rule. Creating a forwarding rule (the write-side
persistence action) is out of scope per G-1/G-3 and is not emulated.

## Borrowed client

## Procedure

1. Operator confirms a valid Graph token from T1078.004 is in scope with MailboxSettings.Read
   consented, and (for cross-user) that the signed-in account holds Exchange Administrator or
   Global Reader. Token acquired and silently reused through scripts/identity.py (ADR 0005).
2. Operator runs `scripts/tool_list_inbox_rules.py` (default `--user-id me`), which issues
   `GET /users/{id}/mailFolders/inbox/messageRules` (v1.0).
3. The forwarding-rule view of the projected output is the T1114.003 surface: for each rule,
   `actions.forwardTo`, `actions.forwardAsAttachmentTo`, and `actions.redirectTo` are extracted
   as plain external addresses — a rule quietly forwarding to an outside address is the
   high-signal finding. The `actions.delete` / `actions.moveToFolder` fields (covering-tracks)
   and the matching conditions are recorded alongside.
4. A `graph_call` replay-log entry is written per G-5. An empty rule set is not an error.

## Guardrails

- G-1 (sandbox tenant only, read-only): all Graph calls target cloudharbordemo
  76b87c33-6178-4ff9-94a7-164792c8e4c6; GET only. Forwarding rules are enumerated, never
  created, modified, or deleted.
- G-3 (borrowed client / read-only scope): MailboxSettings.Read on the borrowed FOCI client
  14d82eec; no inbox-rule write scope.
- G-6 (data redaction): the sandbox tenant GUID is redacted from the tool's evidence output;
  forwarding-target addresses (the indicator) are retained; no message body content is read.
- G-7 (no real user data): only seeded sandbox mailboxes are targeted.
- G-9 (row cap): rule enumeration capped at DEFAULT_ROW_CAP (default 500) applied to total
  rules collected.

## Detection signals

- **Exchange mailbox audit (MailboxAuditLog):** `UpdateInboxRules` / inbox-rule operations
  record rule activity; a rule carrying an external `forwardTo`/`redirectTo` is a high-fidelity
  exfiltration indicator.
- **Unified Audit Log:** `Set-InboxRule` / `New-InboxRule` operations, and the
  `New-TransportRule` org-level analogue.
- **Microsoft Defender for Cloud Apps:** the built-in "suspicious inbox forwarding" /
  inbox-rule-manipulation policies alert on external-forwarding rules; a member account reading
  another mailbox's rules (cross-user) is itself anomalous.
- **MicrosoftGraphActivityLogs:** `GET /mailFolders/inbox/messageRules` from the FOCI client ID
  (14d82eec).

## Limitations

- Rejewski enumerates *existing* forwarding rules (read-only). Creating an email forwarding
  rule — the write-side persistence action T1114.003 describes for an adversary — is out of
  scope under G-1/G-3 and is not emulated.
- Org-level Exchange transport (mail-flow) rules are not available via Microsoft Graph v1.0
  (they require Exchange Online PowerShell) and are out of scope for this Graph-only tool; this
  module covers per-mailbox inbox rules only.
- Cross-user enumeration depends on an Exchange Administrator / Global Reader role; under the
  self-only posture (`--user-id me`) the module is limited to the operator's own mailbox.
