# T1213.002 — Data from Information Repositories: Sharepoint

## Summary

Rejewski will emulate an adversary who enumerates SharePoint Online sites, document
libraries, and lists via Microsoft Graph to map the tenant's information repositories
before any data is read. An adversary who compromises a valid M365 identity can call
GET /sites to enumerate all site collections the account can access, then follow with
GET /sites/{id}/drives and GET /sites/{id}/lists to surface document libraries and
structured data stores within each site. Site names and URLs frequently reveal business
function — names like "HR-Compensation", "Finance-FY2026", or "Legal-Contracts" identify
repositories of high-value documents without reading a single file. Drive and list
metadata reveals file counts, storage consumed, creation dates, and folder structure
depth, giving an attacker a complete inventory of where sensitive data is likely stored
before committing to any content-access calls that carry a higher detection risk.

This technique is catalogued in the Collection tactic because the primary adversary
objective is data repository mapping as a precursor to T1005 (Data from Local System)
or T1530 (Data from Cloud Storage) collection activity. Rejewski's read-only posture
means this module covers repository enumeration only; no file content is read.

## Borrowed client

Microsoft Graph PowerShell (14d82eec-204b-4c2f-b7e8-296a70dab67e). Inherits the
borrowed-client decision from T1078.004; no separate client acquisition occurs.
No tenant-side application registration is created. The no-tenant-app-reg posture
(ADR 0001 §1, threat-model.md §3) is maintained throughout.

**Scope note:** Sites.Read.All is required for cross-tenant site enumeration. This scope
is narrower than the DfI-specific scope flagged in the Tool 7 spike but may not be
pre-consented on the FOCI client in all tenant configurations. Operators must verify
Sites.Read.All consent status in cloudharbordemo before the first Sprint 2 run. If the
scope is not pre-consented, an admin consent grant in cloudharbordemo is required — same
one-time setup pattern as the DfI prerequisite documented in
06 - Research & References/phs-tool7-dfi-spike-2026-06-04.md.

Without Sites.Read.All, the FOCI client can still call GET /me/followedSites and
GET /sites/root to access the caller's personal site and the root site collection. This
narrower scope is a fallback surface with lower coverage; the preferred implementation
uses Sites.Read.All.

## Required privilege

Sites.Read.All delegated scope is required for full cross-site enumeration. No SharePoint
admin role is required — Sites.Read.All grants read access to all site collections the
token's scope covers, not just those the account's role assignments permit. An ordinary
licensed user with this scope consented can enumerate all site collections, which is the
same overly-broad access posture that makes compromised M365 accounts high-value for
adversaries in real engagements.

## Procedure

*Implementation pending Sprint 2. The procedure below defines the expected implementation
shape; it will be updated to reflect the actual script behaviour when Sprint 2 opens.*

1. Operator confirms a valid Graph token from T1078.004 is in scope with Sites.Read.All
   consented.
2. Operator calls GET /sites?search=* to enumerate all accessible site collections.
   Results are paged at default 200/page. Enumeration continues until exhausted or the
   G-9 row cap is hit.
3. For each site, operator records: id, displayName, webUrl, description, createdDateTime,
   lastModifiedDateTime.
4. Operator applies a name-pattern filter against a configurable keyword list (default:
   hr, human resources, finance, legal, payroll, exec, board, confidential, restricted,
   compliance, audit, contracts) to flag high-value sites for follow-on enumeration.
5. For each flagged site, operator calls GET /sites/{id}/drives to enumerate document
   libraries. For each drive: id, name, driveType, quota (total, used, remaining), and
   lastModifiedDateTime are recorded.
6. For each flagged site, operator calls GET /sites/{id}/lists to enumerate SharePoint
   lists and custom lists. For each list: id, displayName, description, list.template
   (documentLibrary, genericList, tasks, etc.), and itemCount are recorded.
7. Operator produces a structured summary: total site count, flagged site count,
   document library count, list count, and the union of all site display names and webUrls.
8. A replay-log entry (kind=graph_call) is written per G-5 requirements for each
   distinct Graph call issued (the /sites search, each /drives call, each /lists call).

## Guardrails

- G-1 (sandbox tenant only): all Graph calls target cloudharbordemo 76b87c33-6178-4ff9-94a7-164792c8e4c6.
- G-3 (read-only scope): GET only; no file reads, no list item reads, no document content
  access. This module covers site and library metadata enumeration only.
- G-5 (evidence capture): replay-log entries written per Graph call; structured site
  inventory in evidence JSON.
- G-6 (audit log redaction): site display names and webUrls are hashed in evidence files
  before any content reaches the public-repo samples/ directory, as they may reveal
  internal business function or personnel details; raw values remain in the operator-side
  SharePoint Evidence folder only.
- G-7 (no real user data): document content, file names, and list item content are not
  read; only site, drive, and list metadata are accessed.
- G-9 (row cap): top-level site enumeration capped at DEFAULT_ROW_CAP (default 1 000
  sites); drives and lists per site are also capped.

## Detection signals

- Graph unified audit log: GET /sites?search=* from the FOCI client ID (14d82eec) is
  logged under the SharePoint audit category. Bulk site enumeration by a non-SharePoint-
  admin account is anomalous and may trigger MDCA alerts in tenants with SharePoint
  activity baselines configured.
- SharePoint Online unified audit log: site-collection reads are also logged in the
  SharePoint audit stream independently of Graph audit events. Defenders correlating
  across both streams can identify enumeration patterns not visible in either stream alone.
- Microsoft Defender for Cloud Apps: Sites.Read.All scope usage at volume (many /sites
  calls in a single session) is a higher-fidelity signal than single-endpoint reads and
  may surface as anomalous data access against a baseline of normal SharePoint API usage.
- Entra ID sign-in logs: correlatable via the T1078.004 session correlation ID.

## Limitations

- GET /sites?search=* enumerates only sites the token's scope and tenant configuration
  allow. Hub sites, private channel sites in Teams, and sites with restricted access
  policies may not appear in the search results even with Sites.Read.All consented.
- This module does not read document content, file names within libraries, or list item
  data. File-level enumeration (GET /sites/{id}/drives/{id}/root/children) and list
  item reads (GET /sites/{id}/lists/{id}/items) are deferred as a Sprint 2+ expansion
  and would require a separate technique attribution review before implementation.
- Personal OneDrive sites (my sites) are a distinct Graph surface accessed via
  GET /users/{id}/drive rather than the /sites endpoint. OneDrive enumeration maps to
  T1530 (Data from Cloud Storage) rather than T1213.002 and is deferred to a separate
  module.
- The cloudharbordemo E5 trial tenant may have few or no custom SharePoint sites beyond
  the root and personal sites. An empty or minimal /sites result is a valid emulation
  outcome and should be documented as a finding (small SharePoint footprint, reduced
  data repository attack surface).
