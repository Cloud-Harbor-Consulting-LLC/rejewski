# T1213.003 — Data from Information Repositories: Code Repositories

## Summary

Rejewski will emulate an adversary who searches the tenant's SharePoint surface for
code-adjacent content — source files, scripts, configuration, infrastructure-as-code, and
deployment artifacts that teams frequently park in SharePoint document libraries rather
than a dedicated source-control system. Code repositories are high-value to an attacker
because they leak hardcoded secrets, connection strings, API keys, internal endpoints, and
architectural detail. GET /sites?search=* enumerates accessible SharePoint sites (some of
which host dev/code content); GET /sites/{site-id}/drives enumerates the document libraries
within a site; and GET /sites/{site-id}/lists enumerates the libraries and custom lists.
Site, library, and list metadata — names like "DevOps", "Build-Scripts", "IaC-Templates",
or "App-Config" — surfaces code-bearing repositories without reading any file content.

This technique is catalogued in the Collection tactic because the adversary objective is
to locate code-bearing repositories as a precursor to secret and source extraction.
Rejewski's read-only posture means this module covers repository *discovery via SharePoint*
only; no file content is read.

## Borrowed client

Microsoft Graph Command Line Tools (14d82eec-204b-4c2f-b7e8-296a70dab67e). Inherits the
borrowed-client decision from T1078.004; no separate client acquisition occurs.
No tenant-side application registration is created. The no-tenant-app-reg posture
(ADR 0001 §1, threat-model.md §3) is maintained throughout.

Sites.Read.All is required for cross-tenant site enumeration — the same scope flagged in
T1213.002. Operators must verify Sites.Read.All consent status in cloudharbordemo before
the first Sprint 2 run; if not pre-consented, a one-time admin consent grant is required
(same setup pattern as the DfI prerequisite). The narrower GET /me/followedSites +
GET /sites/root fallback applies here as in T1213.002.

## Required privilege

Sites.Read.All delegated scope grants read access to the site collections the token's
scope covers; no SharePoint admin role is required. An ordinary licensed user with this
scope consented can enumerate site collections — the same overly-broad access posture that
makes a compromised M365 account high-value to an adversary hunting for code content.

## Procedure

*Implementation pending Sprint 2. The procedure below defines the expected implementation
shape; it will be updated to reflect the actual script behaviour when Sprint 2 opens.*

1. Operator confirms a valid Graph token from T1078.004 is in scope with Sites.Read.All
   consented.
2. Operator calls GET /sites?search=* to enumerate accessible site collections, paging
   until exhausted or the G-9 row cap is hit. Per site: id, displayName, webUrl,
   description, createdDateTime.
3. Operator applies a code-content keyword filter against a configurable keyword list
   (default: dev, devops, build, ci, cd, pipeline, scripts, source, code, repo,
   infrastructure, iac, terraform, config, deploy) to flag candidate code-bearing sites.
4. For each flagged site, operator calls GET /sites/{site-id}/drives to enumerate document
   libraries: id, name, driveType, quota, lastModifiedDateTime.
5. For each flagged site, operator calls GET /sites/{site-id}/lists to enumerate libraries
   and custom lists: id, displayName, description, list.template, itemCount.
6. Operator produces a structured summary: total site count, flagged code-candidate site
   count, document library count, list count, and the union of flagged site display names
   and webUrls.
7. A replay-log entry (kind=graph_call) is written per G-5 requirements for each distinct
   Graph call issued.

## Guardrails

- G-1 (sandbox tenant only): all Graph calls target cloudharbordemo 76b87c33-6178-4ff9-94a7-164792c8e4c6.
- G-3 (read-only scope): GET only; no file reads, no list item reads, no document content
  access. This module covers site and library metadata enumeration only.
- G-5 (evidence capture): replay-log entries written per Graph call; structured site
  inventory in evidence JSON.
- G-6 (audit log redaction): site display names and webUrls are hashed in evidence files
  before any content reaches the public-repo samples/ directory, as they may reveal
  internal project or team names; raw values remain in the operator-side SharePoint
  Evidence folder only.
- G-7 (no real user data): file names within libraries, file content, and list item
  content are not read; only site, drive, and list metadata are accessed.
- G-9 (row cap): top-level site enumeration capped at DEFAULT_ROW_CAP (default 1 000
  sites); drives and lists per site are also capped.

## Detection signals

- Graph unified audit log / MicrosoftGraphActivityLogs: GET /sites?search=* from the FOCI
  client ID (14d82eec), logged under the SharePoint audit category. The call shape is the
  same as T1213.002; the distinguishing factor is the keyword filter applied operator-side
  (code-content keywords vs the high-value-document keywords of T1213.002).
- SharePoint Online unified audit log: site-collection reads are logged in the SharePoint
  audit stream independently of Graph audit events.
- Microsoft Defender for Cloud Apps: Sites.Read.All usage at volume by a non-SharePoint-
  admin account is a higher-fidelity signal than single-endpoint reads.
- Entra ID sign-in logs: correlatable via the T1078.004 session correlation ID.

## Limitations

- **Rejewski's scope is Microsoft Graph read-only.** Native Azure DevOps repositories and
  GitHub repositories require their own APIs (Azure DevOps REST API, GitHub REST/GraphQL
  API) and are outside current scope. This module documents discovery of code-adjacent
  content surfaced **through SharePoint only** — it is not a substitute for enumerating a
  dedicated source-control system, and it will miss any code that lives exclusively in
  Azure DevOps or GitHub.
- This module does not read file content, file names within libraries, or list item data.
  File-level enumeration and content reads are deferred and would require a separate
  technique attribution review before implementation.
- T1213.003 shares its Graph surface (GET /sites, /drives, /lists) with T1213.002
  (SharePoint as a general information repository). The two differ only in the operator-side
  keyword filter and the analyst intent (code content vs high-value documents); when both
  are implemented, the /sites enumeration should be issued once and the result filtered
  twice rather than enumerated twice.
- The cloudharbordemo E5 trial tenant may host little or no code content in SharePoint. An
  empty or minimal code-candidate result is a valid emulation outcome and should be
  documented as a finding (small code-in-SharePoint footprint).
