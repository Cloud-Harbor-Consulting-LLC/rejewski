# T1482 — Domain Trust Discovery

## Summary

Rejewski will emulate an adversary who calls GET /domains to enumerate every domain
registered in the target Entra ID tenant and determine its authentication type. The
domains response includes each domain's name, verification status, authentication type
(Managed or Federated), whether it is the tenant's initial domain (.onmicrosoft.com),
whether it is the default sign-in domain, and which services the domain supports
(Email, OfficeCommunicationsOnline, etc.). The distinction between Managed and Federated
domains is adversarially significant: Managed domains authenticate directly against
Entra ID; Federated domains delegate authentication to an external identity provider
(ADFS, Okta, Ping Identity, Azure AD B2C, or similar). Federated IdPs introduce a
distinct attack surface — SAML token forgery, IdP-side credential attacks, and
conditional access bypass via IdP misconfigurations — that may be absent or differently
configured in the Entra ID layer. An attacker who identifies a federated domain can
redirect authentication attempts to the IdP, potentially bypassing Entra ID-side
detections. GET /domains/{id}/federationConfiguration returns the federation endpoint
and active signing certificate metadata for federated domains, which is the primary
follow-on call once a federated domain is identified.

borrowed-client decision from T1078.004; no separate client acquisition occurs.

(ADR 0001 §1, threat-model.md §3) is maintained throughout.

GET /domains requires Domain.Read.All. This scope is commonly pre-consented on the FOCI
client for tenants with standard M365 delegation configurations. Operators must verify
Domain.Read.All consent status in cloudharbordemo before the first Sprint 2 run. If not
pre-consented, a one-time admin consent grant is required, following the same pattern
as the DfI prerequisite documented in
06 - Research & References/phs-tool7-dfi-spike-2026-06-04.md.

## Required privilege

Domain.Read.All delegated scope is required. No directory role (Domain Administrator,
Global Reader, Global Admin) is required beyond the scope grant; an ordinary licensed
user with Domain.Read.All consented can enumerate all registered domains and read
federation configuration. This makes T1482 runnable at the same privilege tier as
T1087.004 and T1069.003 once the scope is consented.

## Procedure

*Implementation pending Sprint 2. The procedure below defines the expected implementation
shape; it will be updated to reflect the actual script behaviour when Sprint 2 opens.*

1. Operator confirms a valid Graph token from T1078.004 is in scope with Domain.Read.All
   consented.
2. Operator calls GET /domains to enumerate all registered domains. The response is
   typically small (1–20 domains in most tenants); no pagination is expected, but
   the tool will handle @odata.nextLink defensively.
3. Operator extracts and records for each domain: id (the domain name), authenticationType
   (Managed or Federated), isDefault, isInitial, isVerified, isAdminManaged, and
   supportedServices.
4. Operator classifies domains:
   - Initial domain: isInitial=true (the *.onmicrosoft.com domain; always Managed).
   - Default domain: isDefault=true (the domain used for new user UPNs by default).
   - Federated domains: authenticationType=Federated — flagged as high-value.
   - Verified custom domains: isVerified=true and isInitial=false.
   - Unverified domains: isVerified=false — may indicate a domain claimed but not yet
     DNS-verified; lower adversary value but noted.
5. For each Federated domain identified in step 4, operator calls
   GET /domains/{id}/federationConfiguration to retrieve the federation metadata object,
   including: issuerUri, metadataExchangeUri, passiveSignInUri, activeSignInUri,
   signingCertificate, and preferredAuthenticationProtocol (WsFed or SAML).
6. Operator produces a structured summary: total domain count, Managed count, Federated
   count, default domain name, and federation endpoint URIs for any Federated domains.
7. A replay-log entry (kind=graph_call) is written per G-5 requirements for each
   distinct Graph call issued (the /domains list call and each /federationConfiguration
   call).

## Guardrails

- G-1 (consent-bound tenant lock, ADR 0008): all Graph calls target the one tenant named in the run's consent record; the evidence in this repo comes from the cloudharbordemo sandbox (76b87c33-6178-4ff9-94a7-164792c8e4c6).
- G-3 (read-only scope): GET only; no domain registration, no federation configuration
  writes.
- G-5 (evidence capture): replay-log entries written per Graph call; structured domain
  summary in evidence JSON.
- G-6 (audit log redaction): domain names are retained as-is in evidence files (they are
  not PII). Federation endpoint URIs (passiveSignInUri, activeSignInUri) may reveal
  internal IdP hostnames and are redacted in public-repo samples/; raw values remain in
  the operator-side SharePoint Evidence folder only.
- G-7 (no real user data): GET /domains and GET /domains/{id}/federationConfiguration
  return tenant-level configuration only; no per-user data is accessed.
- G-9 (row cap): not applicable — domain counts are small in all known tenant configurations.

## Detection signals

- Graph unified audit log: GET /domains from the FOCI client ID (14d82eec) is logged
  under the directoryManagement audit category. Domain enumeration by a non-Domain-Admin
  account is uncommon in normal delegated usage and may be flagged by MDCA or a SIEM
  with Graph audit log ingestion.
- GET /domains/{id}/federationConfiguration calls are higher-fidelity signals — this
  endpoint is rarely called by non-admin delegated clients in normal operations. A
  sequence of domain list + federation config reads within a single session is a strong
  indicator of reconnaissance intent.
- Entra ID sign-in logs: correlatable via the T1078.004 session correlation ID.
- Microsoft Defender for Cloud Apps: domain-read activity at volume or combined with
  other enumeration calls in the same session may surface as anomalous administrative
  data access.

## Limitations

- The cloudharbordemo E5 trial tenant uses only Managed authentication (no federation
  configured). The /federationConfiguration call will return an empty result or 404 in
  this sandbox, which is itself a valid finding (no external IdP, Entra ID is the sole
  authentication authority). The empty-result case should be documented as a finding
  consistent with the pattern established in the Tool 7 DfI spike.
- External collaboration domains (B2B partner tenants) are not visible via GET /domains;
  that surface is accessible via GET /policies/crossTenantAccessPolicy/partners and is
  deferred to a later technique module.
- GET /domains does not return DMARC, DKIM, or SPF DNS record state. Email authentication
  configuration enumeration via DNS is outside Graph scope and is not included in this
  module.
- The verifiedDomains array in the organization object (T1082) provides the same domain
  names but without the authenticationType or federationConfiguration detail. Operators
  running both T1082 and T1482 should note the overlap in the evidence ledger.
