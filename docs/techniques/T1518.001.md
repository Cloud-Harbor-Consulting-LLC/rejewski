# T1518.001 — Software Discovery: Security Software Discovery

## Summary

Rejewski will emulate an adversary who enumerates the Microsoft 365 security product
stack licensed and active in the target tenant. An adversary with valid cloud credentials
can call GET /subscribedSkus to retrieve every licensed SKU assigned to the tenant,
including service plans within each SKU. From this response, the adversary can determine
with precision which Microsoft security products are active: whether Defender for Endpoint
Plan 1 or Plan 2 is licensed, whether Microsoft Defender for Office 365 (Plan 1 or 2)
is present, whether Microsoft Defender for Identity is deployed, whether Microsoft Purview
compliance and DLP features are available, and whether Microsoft Sentinel ingestion is
configured at the subscription level. This intelligence directly informs adversary
decision-making — it reveals which detection pipelines are present and guides technique
selection for later kill-chain stages.

The technique also surfaces licensing gaps: a tenant with Entra ID P1 but not P2 lacks
Privileged Identity Management and advanced Conditional Access features; a tenant without
Defender for Identity cannot detect certain on-premises Kerberos-based attacks even if
Entra ID is fully covered.

Note: GET /subscribedSkus is also cited in docs/threat-model.md as a deferred T1526
(Cloud Service Discovery) surface. Both attributions are correct — the same Graph call
serves two adversary objectives (service inventory and security posture inventory). This
module governs the security-posture attribution. If a single run enumerates SKUs,
operators should log it under both T1526 and T1518.001 in the replay-log technique array.

## Required privilege

GET /subscribedSkus requires Organization.Read.All or Directory.Read.All — both of
which are typically pre-consented on the Microsoft Graph PowerShell FOCI client in
most M365 tenants. An ordinary licensed user without an elevated directory role can
read subscribed SKUs in many tenant configurations, though behavior varies by tenant
consent state. Rejewski will document the exact scope state against cloudharbordemo
when Sprint 2 implementation opens.

If Directory.Read.All is not pre-consented, the operator must hold at least Global
Reader or License Administrator to read SKU details. This is a higher bar than
T1087.004 or T1069.003 but lower than T1526 (which requires Security Reader).

## Procedure

*Implementation pending Sprint 2. The procedure below defines the expected implementation
shape; it will be updated to reflect the actual script behaviour when Sprint 2 opens.*

1. Operator confirms a valid Graph token from T1078.004 is in scope.
2. Operator calls GET /subscribedSkus to retrieve all licensed SKUs for the tenant.
   The response is typically small (10–50 SKUs in a production tenant; 5–15 in a trial
   sandbox), so no pagination is expected, but the tool will handle @odata.nextLink.
3. Operator parses each SKU's `servicePlans` array to identify security-relevant service
   plan IDs, matching against a local reference table of known security product plan IDs:
   - Defender for Endpoint Plan 1: `WIN_DEF_ATP` family
   - Defender for Endpoint Plan 2 / MDE: `WINDEFATP`
   - Defender for Office 365 Plan 1: `EXCHANGE_ADVANCED_THREAT_PROTECTION`
   - Defender for Office 365 Plan 2: `THREAT_INTELLIGENCE`
   - Defender for Identity: `ATA`
   - Microsoft Purview Information Protection P2: `MIP_S_Exchange`
   - Microsoft Purview Compliance P2: `MICROSOFTPURVIEW_RISK_AND_COMPLIANCE`
   - Microsoft Sentinel: determined via Azure subscription check (out of Graph scope)
   - Entra ID P1: `AAD_PREMIUM`
   - Entra ID P2: `AAD_PREMIUM_P2`
4. Operator produces a structured summary: which security service plans are
   `provisioningStatus: Success` (active), `Disabled` (licensed but turned off),
   or absent entirely.
5. Operator records the SKU count, active security plan count, and disabled plan count
   into the run evidence ledger.
6. A replay-log entry (kind=graph_call) is written per G-5 requirements, with techniques
   array referencing both T1518.001 and T1526 if this call is part of a combined run.

## Guardrails

- G-1 (sandbox tenant only): all Graph calls target cloudharbordemo 76b87c33-6178-4ff9-94a7-164792c8e4c6.
- G-3 (read-only scope): GET only; no license assignment writes.
- G-5 (evidence capture): replay-log entry written per run; SKU summary in evidence JSON.
- G-6 (audit log redaction): SKU display names and plan IDs do not contain PII and are
  retained as-is in evidence files. Seat counts (consumedUnits, prepaidUnits) are
  recorded but not published to the public-repo samples/ directory without review.
- G-7 (no real user data): GET /subscribedSkus returns tenant-level data only; no
  per-user assignment detail is read in the base procedure.
- G-9 (row cap): SKU enumeration is not paged in typical use; cap is applied
  defensively in case the response is unexpectedly large.

## Detection signals

- Graph unified audit log: GET /subscribedSkus call from the FOCI client ID (14d82eec).
  License-read operations are logged under the `subscriptionManagement` audit category.
- Entra ID sign-in logs: correlatable via the T1078.004 session correlation ID.
- Microsoft Defender for Cloud Apps: SKU enumeration is low-frequency and unlikely to
  trigger anomaly detection on its own; however, if chained with T1087.004, T1069.003,
  and T1526 in a single session, the combined read volume may surface as bulk-read
  anomaly activity.

## Limitations

- GET /subscribedSkus returns tenant-level subscription data. It does not reveal which
  specific users have licenses assigned. Per-user license state (useful for identifying
  accounts without Defender coverage) requires GET /users/{id}/licenseDetails or
  GET /users?$select=assignedLicenses — a follow-on surface deferred to Sprint 2.
- Microsoft Sentinel licensing is not discoverable via Graph; it is governed by Azure
  subscription-level resource providers (microsoft.operationalInsights). Sentinel
  presence is therefore inferred (not confirmed) from the presence of an associated
  Microsoft Sentinel plan SKU and is flagged as uncertain in the evidence summary.
- The security plan ID reference table maintained by this tool will require updates when
  Microsoft rebrands or restructures SKUs. The table version is pinned in the script and
  surfaced in the replay-log entry for auditability.
- Disabled service plans (provisioningStatus: Disabled) could mean the plan is turned
  off by admin choice or was part of an expired trial. The tool records the status as-is
  and does not attempt to distinguish the cause.
