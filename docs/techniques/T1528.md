# T1528 — Steal Application Access Token

## Summary

Rejewski catalogues T1528 for its **reconnaissance surface only**: the map an adversary builds
of *which application holds which delegated token against which API* before targeting a specific
service principal for token exfiltration. Two implemented tools produce that map —
`scripts/tool_list_oauth_grants.py` (T1087.004 Surface E) enumerates every OAuth2 delegated
permission grant (clientId, resourceId, consentType, principalId, scope), and
`scripts/tool_list_service_principals.py` (T1087.004 Surface D) enumerates the service principals
those grants belong to, flagging high-value targets (multi-tenant SPs, high-privilege scopes).
Together they answer "who holds a broad admin-consented token I could steal?"

**The actual theft is out of scope.** Rejewski maps the token-target surface; it does not
exfiltrate, replay across clients, or otherwise steal an application access token. This module is
therefore **catalogued** — the reconnaissance is implemented, the credential-access action is
governed out by guardrail.

## Borrowed client

Microsoft Graph Command Line Tools (14d82eec-204b-4c2f-b7e8-296a70dab67e). The FOCI client is
fixed to 14d82eec per ADR 0006 and guardrail G-3; no tenant-side application registration is
created (ADR 0001 §1, threat-model.md §3).

## Procedure

*Reconnaissance surface implemented; the token-theft action is not emulated (see Guardrails and
Limitations).*

1. Operator confirms a valid Graph token from T1078.004 is in scope with the required read
   scopes consented.
2. `scripts/tool_list_oauth_grants.py` issues `GET /oauth2PermissionGrants` and records, per
   grant: clientId (the app holding the delegated permission), resourceId (the API), consentType
   (AllPrincipals admin-wide vs Principal per-user), principalId, and the scope string — plus a
   high-privilege-grant count. This is the shortlist of apps whose delegated authorization would
   be worth stealing.
3. `scripts/tool_list_service_principals.py` issues `GET /servicePrincipals` to resolve those
   clientId/resourceId object IDs to identities and flag high-value targets (multi-tenant SPs,
   broad scopes).
4. A `graph_call` replay-log entry is written per G-5 for each read.

## Guardrails

- G-1 (sandbox tenant only, read-only): all Graph calls target cloudharbordemo
  76b87c33-6178-4ff9-94a7-164792c8e4c6; GET only. No token is read, replayed, or exfiltrated.
- G-2 (no credential modification / no tenant app registration): Rejewski does not create,
  modify, or steal credentials or tokens. The T1528 *action* (stealing an application access
  token) is prohibited by this guardrail; only the read-only reconnaissance surface is emulated.
- G-3 (borrowed client / read-only scope): Directory.Read.All (for `/oauth2PermissionGrants`) and
  Application.Read.All (for `/servicePrincipals`), on the borrowed client 14d82eec.
- G-6 (data redaction): the sandbox tenant GUID is redacted from tool evidence output.
- G-9 (row cap): both enumerations capped at DEFAULT_ROW_CAP.

## Detection signals

- **MicrosoftGraphActivityLogs:** `GET /oauth2PermissionGrants` and `GET /servicePrincipals` from
  the FOCI client ID (14d82eec). Enumeration of the delegated-grant surface is uncommon outside
  admin tooling and is a leading indicator of token-target reconnaissance.
- **Microsoft Defender for Cloud Apps:** an OAuth-app / delegated-grant enumeration read is a
  higher-fidelity signal than a single-endpoint read, especially from a non-admin principal.

## Evidence

*Catalogued — reconnaissance surface partially evidenced.* The R011 sweep (2026-07-18) contains a
successful `tool_list_service_principals.py` `graph_call` entry (T1087.004 Surface D — 415 service
principals, outcome success). `tool_list_oauth_grants.py` (Tool 11) shipped Sprint 3 W11, after
R011, so no committed R-series run includes the delegated-grant read yet; its first evidence will
be captured on a future consented run. The T1528 *action* generates no evidence by design — it is
not emulated.

## Limitations

- **Token theft is not emulated.** Rejewski maps who holds which delegated token; the actual
  exfiltration, cross-client refresh-token replay, or illicit-consent token capture is prohibited
  by G-1 (read-only) and G-2 (no credential modification). Any future emulation of the action
  would require a consent-floor uplift ADR that supersedes the current guardrails.
- Application-permission (app-only) grants — `appRoleAssignments` on service principals — are a
  deferred surface (see T1087.004 Limitations); this module's recon rests on the delegated-grant
  and service-principal surfaces currently implemented.
