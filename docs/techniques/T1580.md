# T1580 — Cloud Infrastructure Discovery

## Summary

Rejewski will emulate an adversary who, holding a valid cloud identity, inventories the
tenant's high-level infrastructure profile before committing to any collection or lateral
movement. The technique reads the tenant organization profile, the set of registered
domains, and the licensed product SKUs to answer three questions an attacker asks early:
what is this tenant, how big and how old is it, and — critically — which Microsoft
security products are licensed and therefore likely watching. GET /organization returns
the tenant display name, creation date, verified domains, and assigned plans;
GET /domains enumerates every domain registered to the tenant (revealing brand surface
and potential federation); GET /subscribedSkus lists the licensed SKUs and their service
plans (E3/E5, Microsoft Defender for Identity, Defender for Endpoint P1/P2, Defender for
Cloud Apps, Entra ID P2). The licensed-SKU inventory is the highest-value output: it
tells the adversary which detection products are *provisioned* in the tenant, directly
informing the detection-coverage assessment that shapes every downstream technique step.

This technique overlaps deliberately with surfaces already catalogued elsewhere; the
attribution boundary is documented in Limitations.

## Borrowed client

Microsoft Graph Command Line Tools (14d82eec-204b-4c2f-b7e8-296a70dab67e). Inherits the
borrowed-client decision from T1078.004; no separate client acquisition occurs.
No tenant-side application registration is created. The no-tenant-app-reg posture
(ADR 0001 §1, threat-model.md §3) is maintained throughout.

The scopes required for this technique (Organization.Read.All, Domain.Read.All,
Directory.Read.All) must be verified as consented on the FOCI client in cloudharbordemo
before the first Sprint 2 run. Directory.Read.All is frequently pre-consented; the
organization- and domain-specific scopes may require a one-time admin consent grant in
the sandbox — the same setup pattern documented for the DfI prerequisite.

## Required privilege

Any ordinary licensed user with the read scopes above consented via the FOCI client can
call all three endpoints. No directory role is required for GET /organization,
GET /domains, or GET /subscribedSkus — these are tenant-wide read surfaces available to
any authenticated member. This keeps T1580 at the same low privilege tier as the other
Discovery-leg techniques, runnable immediately after the T1078.004 initial-access step.

## Procedure

*Implementation pending Sprint 2. The procedure below defines the expected implementation
shape; it will be updated to reflect the actual script behaviour when Sprint 2 opens.*

1. Operator confirms a valid Graph token from T1078.004 is in scope with
   Organization.Read.All, Domain.Read.All, and Directory.Read.All consented.
2. Operator calls GET /organization and records: id, displayName, createdDateTime,
   verifiedDomains, onPremisesSyncEnabled (hybrid signal), assignedPlans, and
   technical/security notification contacts.
3. Operator calls GET /domains and records each domain's id (the domain name),
   isVerified, isDefault, authenticationType (Managed vs Federated), and supportedServices.
4. Operator calls GET /subscribedSkus and records each SKU's skuPartNumber,
   capabilityStatus, consumedUnits, prepaidUnits, and the servicePlans array.
5. Operator derives a security-product posture summary from the service plans: which
   Defender products (DfI, Defender for Endpoint, Defender for Cloud Apps), Entra ID P1/P2
   features, and audit/retention plans are licensed and in `Enabled` capabilityStatus.
6. Operator produces a structured profile: tenant identity, age, domain count, federated
   domain count, licensed-SKU count, and the security-product coverage map.
7. A replay-log entry (kind=graph_call) is written per G-5 requirements for each distinct
   Graph call issued.

## Guardrails

- G-1 (sandbox tenant only): all Graph calls target cloudharbordemo 76b87c33-6178-4ff9-94a7-164792c8e4c6.
- G-3 (read-only scope): GET only; no organization, domain, or license write operations.
- G-5 (evidence capture): replay-log entry written per Graph call; aggregate profile in evidence JSON.
- G-6 (audit log redaction): tenant display name, domain names, and notification-contact
  addresses are hashed in evidence files before any content reaches the public-repo
  samples/ directory; raw values remain in the operator-side SharePoint Evidence folder only.
- G-7 (no real user data): only the seeded sandbox tenant's own configuration is read.
- G-9 (row cap): domain and SKU enumeration capped at DEFAULT_ROW_CAP (default 1 000).

## Detection signals

- Graph unified audit log / MicrosoftGraphActivityLogs: GET /organization,
  GET /domains, and GET /subscribedSkus from the FOCI client ID (14d82eec) in a single
  session is a recognisable cloud-infrastructure-profiling pattern when correlated by
  client ID and session.
- Microsoft Defender for Cloud Apps: bulk configuration reads by a non-admin account may
  surface as anomalous activity against a baseline of normal API usage.
- Entra ID sign-in logs: correlatable via the T1078.004 session correlation ID.
- Note the reflexive signal: an adversary reading /subscribedSkus is specifically trying
  to learn whether *these very detection products* are licensed. Defenders should treat
  license-inventory reads from a member account as a high-context recon indicator.

## Limitations

- This technique overlaps three already-catalogued surfaces by design and the attribution
  boundary is intentional:
  - GET /organization is the primary surface of T1082 (System Information Discovery) and
    a deferred T1526 surface. T1580 reads it for the broader *infrastructure profile*
    (org + domains + licenses together), not as a standalone system-info read.
  - GET /subscribedSkus is the catalogued surface of T1518.001 (Security Software
    Discovery). T1580 uses it for the licensed-SKU *inventory*; T1518.001 reads it to
    assess active security-software posture specifically. When both are implemented, the
    license read should be issued once and shared, not duplicated per technique.
  - GET /domains is also exercised by T1482 (Domain Trust Discovery). T1580 records domain
    *existence and count*; T1482 analyses federation/trust relationships per domain.
- The cloudharbordemo E5 trial tenant rotates licensing; the SKU set observed on any one
  run is a point-in-time snapshot and may differ between runs. This is a valid emulation
  outcome and should be recorded as a finding rather than treated as drift.
- No Azure resource-manager (ARM) infrastructure (subscriptions, resource groups, VMs) is
  in scope — Rejewski reads Microsoft Graph only. ARM-level cloud infrastructure discovery
  requires the Azure Resource Manager API, outside current scope.
